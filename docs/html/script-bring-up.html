مسیر فایل: scripts/bring_up.sh

۱. کاراییش به زبان ساده

این اسکریپت همان دکمهٔ «پروژه را برایم بالا بیاور» است. روی ماشین تازه یا سرور نصب‌شده اجرا می‌شود، فایل‌های محیطی گم‌شده را از نمونه‌ها می‌سازد (بدون بازنویسی فایل‌های موجود)، اعتبارنامه‌های خالی Postgres را پر می‌کند، کل Docker Compose را بالا می‌آورد، منتظر می‌ماند تا سرویس‌ها واقعاً قابل استفاده شوند، و در پایان Smoke Test زیرساخت (check_infra.sh) را اجرا می‌کند. نصب Docker روی سیستم‌عامل را انجام نمی‌دهد؛ آن کار عمداً به اپراتور یا Ansible سپرده شده است.

۲. کجا در پروژه کلی استفاده می‌شود؟

  • نقطهٔ ورود توصیه‌شده برای راه‌اندازی اولیه و بالا آوردن روزمرهٔ استک (طبق docs/setup.md و scripts/README.md).
  • جایگزین فراخوانی دستی و پراکندهٔ docker compose up برای اپراتورهایی که می‌خواهند env، wait و smoke check یک‌جا انجام شود.
  • با فلگ --with-cycle-reports سرویس Compose به نام cycle-reporter را هم فعال می‌کند که داخلش finalize_cycle_reports.py در حلقه اجرا می‌شود.
  • با فلگ --infra-only فقط لایهٔ داده و ابزارهای کمکی را بالا می‌آورد تا توسعهٔ host/venv روی App API و Crawler ممکن باشد.
  • نیمهٔ Shell از «نصب و راه‌اندازی» است؛ نیمهٔ Ansible در پوشهٔ ansible/ عمداً جدا مانده و اینجا صدا زده نمی‌شود.

۳. چیکارا می‌کند؟ (مراحل اجرا)

  1. پیش‌نیازها: وجود docker و پلاگین Compose روی PATH، و در دسترس بودن daemon داکر.
  2. فایل‌های .env: اگر .env ریشه و envهای زیرسیستم‌ها نباشند، از *.env.example کپی می‌شوند؛ هرگز روی فایل موجود overwrite نمی‌کند.
  3. اعتبارنامهٔ Postgres: اگر POSTGRES_DB / USER / PASSWORD خالی باشند، مقادیر معقول (و برای پسورد، تصادفی) می‌نویسد و همان را به envهای host-side مربوط به app_api و storage_consumer آینه می‌کند تا mismatch رخ ندهد.
  4. Compose up:
    • حالت کامل: infra (postgres، zookeeper، kafka، kafka-init، kafka-ui، metabase) + اپ‌ها (app-api، storage-consumer، crawler) و با پروفایل tools یک‌بار network-analyzer.
    • حالت --infra-only: فقط مجموعهٔ infra بالا.
  5. انتظار آمادگی: Postgres، Kafka، App API، Storage Consumer؛ همچنین اطمینان از وجود دیتابیس metabase_app_db (idempotent؛ برای volumeهایی که قبل از init ساخته شده‌اند).
  6. Smoke check: مگر با --skip-check، اسکریپت scripts/infra/check_infra.sh را صدا می‌زند.

نکته دربارهٔ network-analyzer: این سرویس یک job دسته‌ای است (inbox را پردازش می‌کند)، نه daemon دائمی. در bring-up کامل یک‌بار با بقیه بالا می‌آید؛ اگر inbox خالی باشد معمولاً سریع خارج می‌شود.

۴. تصمیمات معماری

  • جدا بودن از Ansible: نصب OS/Docker کار provisioning است؛ این اسکریپت فقط bootstrap داخل مخزن کلون‌شده است تا مرز مسئولیت شفاف بماند.
  • هرگز overwrite نکردن .env: جلوگیری از از دست رفتن تنظیمات اپراتور روی سرور زنده.
  • آینه‌کردن credentials: یک منبع حقیقت برای Postgres در root .env، و همگام‌سازی envهای host تا تست/اجرای محلی گیر نکند.
  • Metabase در INFRA نه APP: مثل Kafka UI یک ابزار ops است، فقط به Postgres سالم نیاز دارد، و در حالت --infra-only هم مفید است.
  • network-analyzer پشت profile tools: تا استک پیش‌فرض با jobهای دسته‌ای شلوغ نشود، ولی bring_up کامل عمداً آن پروفایل را فعال می‌کند.
  • Wait قبل از smoke: «کانتینر بالا آمده» با «سرویس آماده است» یکی نیست؛ بدون wait، check_infra نویز کاذب می‌دهد.
  • Exit معنادار از check: اگر smoke fail شود، اپراتور بلافاصله می‌فهمد استک «بالا آمده اما سالم نیست».

۵. دستورات

# از ریشهٔ مخزن
./scripts/bring_up.sh

# فقط زیرساخت (Postgres / ZooKeeper / Kafka / UI / Metabase)
./scripts/bring_up.sh --infra-only

# استک کامل + گزارش‌های چرخه (crawler pending + cycle-reporter)
./scripts/bring_up.sh --with-cycle-reports

# رد کردن smoke check
./scripts/bring_up.sh --skip-check

# استفاده از imageهای از قبل build‌شده
./scripts/bring_up.sh --no-build

./scripts/bring_up.sh --help

پیش‌نیاز: Docker Engine + پلاگین Compose، اجرا از ریشهٔ کلون مخزن.

گام بعدی پیشنهادی پس از موفقیت:

./scripts/verify/verify_storage_consumer.sh
