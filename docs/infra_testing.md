<font size=6>
<b>مستندات تست زیرساخت پروژه</b>
</font>

<br>
<p align="justify">
<font size=4>
پیش از شروع پیاده‌سازی هر بخش از منطق برنامه (Django، Crawler و ...)، لازم بود از سلامت و آماده‌به‌کار بودن زیرساخت پایه‌ی پروژه (PostgreSQL و Kafka) اطمینان حاصل شود. برای این منظور، به‌جای بررسی دستی و پراکنده، یک اسکریپت Smoke Test خودکار در مسیر <code>scripts/check_infra.sh</code> نوشته شده است که این بررسی را به‌صورت یکپارچه و تکرارپذیر انجام می‌دهد.
</font>
</p>

<font size=5>
<b>پیش‌نیازها</b>
</font>

<br>
<p align="justify">
<font size=4>
پیش از اجرای اسکریپت باید موارد زیر انجام شده باشد:
</font>
</p>

<ol>
<font size=4>
<li>فایل <code>.env</code> بر اساس نمونه‌ی موجود ساخته و مقادیر آن تنظیم شده باشد.</li>
<li>سرویس‌های زیرساختی با دستور زیر بالا آمده باشند:</li>
</font>
</ol>

</div>
</font>

```bash
cp .env.example .env
# edit the .env values
docker compose up -d postgres zookeeper kafka
```

<font size=5>
<b>خروجی و نحوه‌ی تفسیر آن</b>
</font>

<br>
<p align="justify">
<font size=4>
اسکریپت برای هر مرحله یکی از سه وضعیت زیر را نمایش می‌دهد:
</font>
</p>

<ul>
<font size=4>
<li><b>[OK]</b> — مرحله با موفقیت انجام شده است.</li>
<li><b>[FAIL]</b> — مرحله ناموفق بوده و جزئیات خطا (در صورت وجود) بلافاصله زیر آن چاپ می‌شود.</li>
<li><b>[..]</b> — مرحله در حال انجام است (وضعیت میانی، صرفاً برای اطلاع‌رسانی).</li>
</font>
</ul>

<p align="justify">
<font size=4>
در پایان اجرا، یک خط جمع‌بندی نمایش داده می‌شود:
</font>
</p>

<ul>
<font size=4>
<li>اگر همه‌ی بررسی‌ها موفق باشند: پیام موفقیت نمایش داده شده و اسکریپت با <code>exit code 0</code> خارج می‌شود.</li>
<li>اگر حداقل یک بررسی ناموفق باشد: تعداد بررسی‌های ناموفق نمایش داده شده و اسکریپت با <code>exit code 1</code> خارج می‌شود.</li>
</ul>
</font>

<p align="justify">
<font size=4>
Exit Code معنادار به‌طور خاص برای این در نظر گرفته شده که این اسکریپت بعداً در مراحل توسعه‌ی بعدی پروژه (مثلاً یک اسکریپت بزرگ‌تر نصب end-to-end) بتواند به‌عنوان یک پیش‌شرط (Precondition) فراخوانی شود؛ یعنی مراحل بعدی نصب تنها زمانی اجرا شوند که زیرساخت واقعاً سالم باشد.
</font>
</p>

<font size=5>
<b>نکات و ملاحظات طراحی</b>
</font>

<br>
<p align="justify">
<font size=4>
<ul>
<li><b>مقاوم در برابر خطای جزئی:</b> اسکریپت با اولین خطا متوقف نمی‌شود؛ بلکه تمام بررسی‌ها را تا انتها اجرا کرده و در پایان یک گزارش کامل ارائه می‌دهد. این باعث می‌شود در صورت بروز مشکل، به‌جای یک خطای مبهم، دقیقاً مشخص باشد کدام سرویس و کدام مرحله دچار مشکل شده است.</li>
<br>
<li><b>مکانیزم Retry:</b> برای هر دو سرویس، اسکریپت چند بار (با فاصله‌ی زمانی) تلاش می‌کند پیش از اعلام شکست؛ چون معمول است که سرویس‌هایی مثل Kafka چند ثانیه پس از بالا آمدن کانتینر، زمان نیاز داشته باشند تا کاملاً آماده‌ی پاسخ‌گویی شوند.</li>
<br>
<li><b>عدم وابستگی به کد پایتون پروژه:</b> این اسکریپت عمداً فقط از ابزارهای موجود در خودِ Image ها (psql، ابزارهای CLI کافکا) استفاده می‌کند و به هیچ کتابخانه یا کد اپلیکیشنی وابسته نیست؛ بنابراین می‌تواند مستقل و پیش از نوشتن هر خط کد پایتون اجرا و اعتبارسنجی شود.</li>
<br>
<li><b>پاکسازی خودکار داده‌ی تستی:</b> هم جدول موقت در Postgres و هم Topic تستی در Kafka، در پایان اجرا حذف می‌شوند تا زیرساخت پس از تست دقیقاً در همان وضعیت اولیه (بدون داده‌ی اضافی) باقی بماند.</li>
</ul>
</font>
